# 펌웨어 설계

기반: ESP-IDF (FreeRTOS), C. 하드웨어와 무관한 논리는 `firmware/core/`에 두고 PC에서 테스트한다.

## 1. 구조

```
 키 매트릭스 ─▶ input ─▶ keymap ─▶ hangul ─▶ editor ─▶ ui ─▶ 메모리 LCD
 (GPIO)        스캔      레이어    조합       항목 버퍼   바뀐 줄만 그리기
               디바운스  원샷/고정              │
                                               ▼
                                             store ──▶ 플래시 (LittleFS, JSONL 저널)
                                               │
                                               ▼
                                             sync ──▶ BLE / HTTPS / USB
```

| 모듈 | 책임 | 위치 |
|---|---|---|
| `input` | 매트릭스 스캔, 선등록 디바운스, 키 이벤트 큐 | 기기 전용 |
| `keymap` | 어깨 버튼 레이어(누름·원샷·고정), 키 → 자모·문자·명령 | core |
| `hangul` | 두벌식 조합 (구현됨) | core |
| `editor` | 현재 항목의 텍스트 버퍼, 커서, 항목·메모 이동 | core |
| `store` | 저널 쓰기·읽기, 일련번호, 색인 | core + 플래시 드라이버 |
| `ui` | 글꼴 렌더링, 상태 줄, 메뉴 | 기기 전용 |
| `sync` | 전송 규약, 대상별 커서 | core + 전송 계층 |
| `power` | 슬립 진입·복귀, 배터리 | 기기 전용 |

`core`는 동적 할당 없이 표준 C만 쓰고, 플래시·전송은 함수 포인터 인터페이스로 받는다.

## 2. 태스크와 지연

| 태스크 | 우선순위 | 동작 |
|---|---|---|
| input | 높음 | 타자 중 1 ms 타이머로 스캔. 2초간 입력이 없으면 스캔을 멈추고 GPIO 인터럽트 대기 |
| edit/ui | 중간 | 키 이벤트를 받아 조합·편집 후 바뀐 화면 줄만 SPI로 전송 |
| store | 낮음 | 항목 확정 시, 또는 입력이 2초 멈추면 저널에 기록 |
| sync | 낮음 | 전송 요청이 있을 때만 무선을 켬 |

키 누름에서 화면 반영까지 20 ms 이내가 목표다. 메모리 LCD는 줄 단위로 갱신할 수 있어서 글자 한 줄(16~20 화소 줄)만 보내면 된다.

## 3. 저장

- 내장 플래시의 데이터 파티션(약 5 MB)에 LittleFS.
- 저널은 추가 전용이다. `/j/000001.jsonl`, `/j/000002.jsonl` … 각 256 KB에서 다음 파일로 넘어간다.
- 한 줄 = 항목의 한 리비전 ([형식](data-and-sync.md)). 수정은 같은 `id`에 `rev`를 올린 새 줄, 삭제는 `deleted: true`인 줄이다.
- 쓰는 중인 항목은 입력이 2초 멈출 때마다 `/draft`에 덮어써 두고, 부팅 때 남아 있으면 복구한다. 전원이 갑자기 끊겨도 잃는 것은 마지막 2초다.
- 부팅 시 저널을 훑어 `id → (파일, 위치, rev)` 색인을 RAM에 만든다. 마지막 줄이 깨져 있으면(쓰는 도중 전원 차단) 그 줄만 버린다.
- 정리: 모든 전송 대상이 받아 간 구간에서, 더 새 리비전이 있는 옛 줄을 지운다. 사용자가 지우지 않은 최신 리비전은 계속 보관한다.

용량: 항목 하나가 약 250바이트면 5 MB에 약 2만 항목이 들어간다.

## 4. 화면

세로 240 × 400 화소.

```
┌──────────────┐
│ 11/11 3/7  ▮▮│  상태 줄: 날짜, 메모 안 항목 위치, 배터리, 전송 대기 수
├──────────────┤
│ 앞 항목 (흐리게)│
│              │
│ 현재 항목     │  16 px 글꼴: 한 줄 한글 15자
│ 조합 중인 글자█│  20 px 글꼴: 한 줄 한글 12자 (설정)
│              │
├──────────────┤
│ 한 ⇧ ①        │  입력 모드, 원샷/고정 표시
└──────────────┘
```

- 글꼴은 재배포 가능한 한글 비트맵 글꼴(OFL 계열)을 플래시에 넣는다. 완성형 11,172자 × 16 × 16 ≈ 360 KB.
- 현재 항목이 항상 화면 가운데 근처에 오도록 스크롤한다.
- 화면 반전(극성 신호)은 RTC 타이머로 1 Hz 유지한다.

## 5. 전원

| 상태 | 진입 | 무선 | CPU |
|---|---|---|---|
| 타자 | 키 입력 | 꺼짐 | 80 MHz, 자동 라이트 슬립 |
| 대기 | 2초 무입력 | 꺼짐 | 라이트 슬립, 키 인터럽트로 복귀 |
| 전송 | `기능 + ↵`, 또는 설정한 자동 조건 | 켜짐 | 동작 |
| 꺼짐 | `기능 + 메뉴` 2초 | 꺼짐 | 딥 슬립, 메뉴 키로 복귀 |

자동 전송 조건(설정): 끄기 / 충전기 연결 시 / 대기 N분마다.

## 6. 설정

`/config.json`에 저장하고 기기 메뉴, BLE, USB로 바꿀 수 있다.

```json
{
  "font_px": 16,
  "layout": "dubeolsik",
  "long_press_double": false,
  "straddle_filter": false,
  "auto_cap": false,
  "auto_sync": "off",
  "wifi": [{ "ssid": "..." }],
  "server": { "url": "https://example.com/dpn", "token_set": true },
  "tz": "+09:00"
}
```

Wi-Fi 암호와 서버 토큰은 이 파일이 아니라 암호화된 NVS에 저장하고 어떤 경로로도 다시 읽어 주지 않는다. 기기에 키보드가 있으므로 Wi-Fi 정보는 기기에서 직접 입력할 수도 있다.

## 7. 구현 순서

1. `keymap`, `editor`, `store`를 core에 작성하고 호스트 테스트 (터미널에서 동작하는 시뮬레이터 포함)
2. 개발보드에서 `input` + `ui` 연결 → 타자 가능
3. USB 드라이브 내보내기 → BLE → HTTPS 순으로 `sync`
4. `power` 최적화와 전류 실측
