# 하드웨어 설계

## 1. 폼팩터: 왜 이 모양인가

손에 쥐고 치는 속도와 정확도를 정하는 요인은 네 가지다.

1. **엄지가 한 키를 정확히 고를 수 있는가** — 키 간격이 엄지 접촉 폭(약 10 mm)보다 많이 작으면 옆 키를 함께 누른다.
2. **눌렸는지 손끝으로 아는가** — 촉각 피드백이 없으면 눈이 키와 화면을 오가야 한다.
3. **손을 고쳐 쥐지 않고 모든 키에 닿는가** — 그립을 바꾸는 순간 리듬이 끊긴다.
4. **두 엄지가 번갈아 치는가** — 한 엄지가 연속으로 치는 것보다 교대가 빠르다.

검토한 형태:

| 형태 | 판단 |
|---|---|
| 세로형 + 하단 미니 쿼티 (키 간격 약 6 mm) | 촉각은 좋지만 키가 엄지보다 작아 1번을 만족하지 못한다. |
| 가로형 + 전폭 10열 키보드, 화면은 위 | 안쪽 열까지 55 mm 넘게 뻗어야 하고, 화면이 얇은 띠가 된다. |
| 코드(chord) 키보드, 뒷면 키 | 이론상 빠르지만 익히는 데 몇 주가 걸리고 키가 보이지 않는다. |
| 천지인류 12키 | 키가 커서 정확하지만 글자당 누름 횟수가 많다. |
| **가로형 + 화면 중앙 + 좌우 분할 5열** | 채택. 아래 참조. |

채택한 형태는 게임패드처럼 양손으로 쥔다. 아래 모서리가 손바닥에 걸리고, 엄지는 좌우 키 묶음 위에, 검지는 윗면 어깨 버튼 위에 놓인다.

- 화면이 가운데 있어 각 엄지가 맡는 영역이 가로 45 mm × 세로 40 mm로 줄어든다.
- 키 묶음은 본체의 아래쪽에 둔다. v0.1에서는 위쪽에 뒀지만 [타자 시뮬레이션](simulation.md)에서 아래쪽이 작은 손에 7% 유리하게 나와 v0.2에서 10 mm 내렸다. 손은 기기를 아래에서 받쳐 쥐고 엄지가 위를 향하는 자세가 최적으로 나온다.
- 시선은 가운데 화면에 고정되고 키는 양옆 주변 시야에 들어온다.
- 두벌식은 자음이 왼쪽, 모음이 오른쪽이라 한글에서는 거의 매 타가 좌우 교대가 된다.

## 2. 치수

| 항목 | 값 |
|---|---|
| 외형 | 142 × 70 × 12.1 mm (키캡 1 mm 돌출 별도) |
| PCB | 138 × 66 × 1.0 mm, 모서리 R6 |
| 키 | 좌우 각 5열 × 4행, 간격 9.0 × 10.0 mm, 키캡 윗면 7.4 × 8.4 mm |
| 스위치 수 | 앞면 38개(스페이스 바 2개는 스위치 2개 병렬) + 어깨 2개 |
| 디스플레이 창 | 36.3 × 59.8 mm (세로 240 × 400 px) |
| 예상 무게 | 85~95 g (배터리 약 20 g 포함, 추정) |

전체 치수 계약은 [`hardware/case/dpn_core.scad`](../hardware/case/dpn_core.scad)에 있다.

## 3. 주요 부품

| 기능 | 기준 부품 | 선택 이유 / 비고 |
|---|---|---|
| MCU·무선 | ESP32-S3-MINI-1 (N8) | BLE 5 + Wi-Fi + USB OTG를 한 모듈로. 플래시 8 MB. |
| 디스플레이 | Sharp LS027B7DH01 (2.7", 400 × 240, 반사형 메모리 LCD) | 화소가 상태를 기억해 상시 표시 전력이 µW 단위, 갱신이 즉각적, 햇빛 아래서도 보임. **정격 VDD가 5 V이므로 소형 승압 회로가 필요한지 데이터시트로 확인할 것.** |
| 키 스위치 | 4 × 3 mm급 SMD 택트 스위치, 누름 압력 약 1.0 N (예: Alps SKRP 계열 저하중품) | 낮은 높이(2 mm), 뚜렷한 클릭. 1.6 N 이상은 장시간 타건에 무겁다. 0단계에서 0.7 / 1.0 / 1.6 N을 비교해 확정. |
| 어깨 버튼 | 측면 누름(right-angle) 택트 스위치 × 2 | PCB 뒷면 위 모서리, x = ±50 mm. 시뮬레이션의 최적 그립에서 검지가 닿는지 확인되지 않아 목업에서 검증하고, 닿지 않으면 뒷면으로 옮긴다. |
| 다이오드 | 키마다 1개 (1N4148WS 등) | 여러 키가 겹쳐 눌려도 정확히 읽기 위함 |
| 배터리 | 리튬폴리머 503450 (1000 mAh, 보호회로 내장) | 디스플레이 뒤에 배치 |
| 충전 | USB-C + 단일 셀 충전 IC (예: BQ24074, 전원 경로 포함) | 충전 중에도 사용 가능 |
| 3.3 V 전원 | 저대기전류 벅 컨버터 (예: TPS62840) | Wi-Fi 송신 피크(약 350 mA)를 감당하면서 대기 전류가 작아야 함 |
| 잔량 측정 | 연료 게이지 IC (예: MAX17048) | 전압 추정보다 정확, I²C |
| 시계 | ESP32 내부 RTC + 32.768 kHz 크리스털 | 전송할 때마다 상대 기기에서 시각을 받아 맞춤. 배터리가 완전히 방전되면 시각을 잃고, 그 동안의 레코드는 `clock: "unsynced"`로 표시된다. |
| 기타 | 상태 LED 1개, 리셋 핀홀 | 진동·스피커는 넣지 않는다(스위치 클릭이 피드백). |

핀 사용: 키 매트릭스 4행 × 10열 = 14, 디스플레이 SPI 5(SCLK, MOSI, CS, DISP, EXTCOMIN), I²C 2, USB 2, 충전 상태 1, LED 1 — 모듈의 가용 GPIO 안에 들어간다. 어깨 버튼 2개는 4행의 빈 매트릭스 자리를 쓴다.

## 4. 배치

원점은 PCB 중심, +y가 위(어깨 버튼 쪽).

**앞면**
- 디스플레이: 중앙, 세로 방향 (모듈 42.8 × 62.8 mm)
- 키: 열 중심 x = ±(28 + 9·i), i = 0…4 / 행 중심 y = 9, −1, −11, −21
- 4행은 안쪽 3칸이 스페이스 바(양 끝에 스위치 2개), 바깥 2칸이 단독 키

**뒷면**
- 배터리: 중앙 (34 × 50 × 5 mm), 중심 y = +4
- ESP32-S3 모듈: 오른쪽 위, 안테나가 위 모서리를 향함. x 24~40, y 25~33 구간은 안테나 금지 구역(동박·금속·배터리 금지)
- USB-C: 아래 모서리 중앙
- 어깨 스위치: 위 모서리 x = ±50
- 전원·충전 회로: 왼쪽 위 (모듈 반대편)

안테나를 위 모서리에 두는 이유는 아래 모서리 양쪽을 손바닥이 감싸기 때문이다.

**두께 방향** (PCB 앞면 = 0)

| 구간 | 내용 |
|---|---|
| +4.1 ~ +5.1 | 키캡 돌출 |
| +2.7 ~ +4.1 | 앞판 |
| +2.2 ~ +2.6 | 키매트 시트 |
| 0 ~ +2.0 | 스위치 / 디스플레이(1.9) |
| −1.0 ~ 0 | PCB |
| −6.6 ~ −1.0 | 배터리·모듈·커넥터 공간 |
| −8.0 ~ −6.6 | 뒷판 |

## 5. 전력 (계산값, 미실측)

원칙: 무선은 전송할 때만 켜고, 키 입력 사이에는 라이트 슬립으로 들어간다. 대기 중에는 모든 열을 구동해 두고 행 입력의 GPIO 인터럽트로 깨어난다.

| 상태 | 가정한 평균 전류 | 하루 사용 | 하루 소모 |
|---|---|---|---|
| 대기 (화면 켜짐, 라이트 슬립) | 0.4 mA | 23 h | 약 9 mAh |
| 타자 중 | 15 mA | 1 h | 약 15 mAh |
| 전송 (BLE 또는 Wi-Fi) | 100 mA | 3 분 | 약 5 mAh |

합계 약 30 mAh/일 → 1000 mAh로 약 한 달. 2단계에서 실측해 표를 갱신한다.

## 6. 디스플레이를 바꾸고 싶다면

디스플레이 자리는 44 × 64 mm, 높이 1.9 mm까지 허용한다. PCB에는 FPC 커넥터와 함께 SPI 신호를 8핀 패드로도 뽑아 둔다. 이 자리에 들어가는 2.13" 전자종이(약 59 × 29 mm) 같은 패널로 바꿀 수 있지만, 전자종이는 부분 갱신이 수백 ms 걸려 타자 피드백이 늦어지므로 기준 설계로는 권하지 않는다.
